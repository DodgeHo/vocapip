# ADR-0004: Compact anchored pet surface and native interaction model

- Status: Accepted
- Date: 2026-08-18

## Context

The original main window is a fixed `360×640` transparent, borderless surface. The visible pet occupies only part of that rectangle, leaving a large blank hit area that can cover or capture input intended for other Windows applications. The progress strip, toolbar, and pet are spatially separated, so the surface reads as a broken panel rather than a desktop pet. The pet also lacks discoverable window-layer controls and complete left- and right-click behavior.

VocaPip must remain a low-interruption Windows companion. The redesign must preserve the existing learning flow, FSRS scheduling, XP, SQLite persistence, tray behavior, settings, wordbook, and offline runtime constraints.

## Decision

Replace the fixed main panel with a compact, dynamically sized pet surface controlled by four frontend modes: `idle | learning | progress | placement`.

### Geometry and anchoring

- `idle` uses a fixed `232×258` logical-pixel window that encloses only the pet, its progress base, and the hide and pin controls.
- `learning` expands to approximately `384×620` logical pixels.
- `progress` expands only enough to contain the attached progress-detail popover; it does not open a separate main panel.
- `placement` uses approximately `420×620` logical pixels for the first-run level placement flow.
- The pet's foot-center is the stable screen anchor. Resizing preserves that anchor, then clamps the complete visible surface to the current monitor work area.
- Geometry is calculated in logical pixels and must account for Windows 100%, 125%, and 150% scaling, monitors with negative coordinates, and work areas that exclude the taskbar.
- The learning bubble normally opens above the pet and flips below it when the upper work area is insufficient. Horizontal placement is clamped to the work area.

### Window layer and closing behavior

- “Front” means `always on top`; “back” means normal window z-order.
- No click-through mode is introduced. Click-through would conflict with the required learning click and drag gesture and would make recovery less discoverable.
- A visible pin control toggles normal/always-on-top state through the existing persisted setting path.
- Closing the learning or progress surface returns to `idle`. Closing the main window hides it to the tray. Process termination remains an explicit tray or context-menu action.

### Pointer interaction

- A left-button press and release without significant movement opens or focuses the learning bubble.
- Pointer movement greater than `6px` changes the gesture to native window dragging and suppresses the learning click generated by that gesture.
- Right-clicking the pet opens a Windows native context menu containing: learn one word, normal/always-on-top, pause/resume reminders, wordbook, settings, hide to tray, and exit.
- Native-menu actions that only affect the process or windows should execute in Rust. Actions that change the learning surface are delivered to the frontend through a narrow application event.
- Double-click and click-through behaviors are not part of this interaction model.

### Progress and visual feedback

- Replace the detached top progress strip with a stable progress base directly beneath the pet.
- The base displays today's completed/goal count, level, and XP fill. It is a button for opening details, not a slider or editable progress control.
- The attached detail popover shows today's goal, reviews due, streak, and XP remaining to the next level; clicking the base again or losing focus closes it.
- Rating feedback and XP movement terminate at the progress base. Upgrade feedback affects both the pet pose and level indicator.
- Replace the block-built character with project-authored layered SVG artwork using a rounded sticker silhouette, dark outline, mint body, and restrained coral/yellow accents.
- Idle, click, error, correct, and upgrade states remain distinguishable when reduced motion is enabled.

### Security and assets

- The redesign adds no HTTP, WebSocket, updater, telemetry, online dictionary, remote font, remote image, or AI runtime dependency.
- Pet artwork is authored for VocaPip, distributed under GPL-3.0-or-later with the application, and has no external character-asset dependency.
- Window commands and events remain narrow; the frontend is not granted generic shell, network, filesystem, or broad window-management permissions.

## Alternatives considered

### Keep the fixed transparent window

Rejected because invisible pixels still participate in window hit testing and interfere with other applications. Rearranging controls inside the same rectangle would not solve the primary defect.

### Add click-through as the “back” mode

Rejected for this iteration because it conflicts with left-click learning, dragging, and right-click discovery. Normal z-order provides a predictable “back” state without making the pet unreachable.

### Put progress only inside the learning bubble

Rejected because idle-state progress is part of the motivational loop. The attached base preserves visibility while keeping the desktop footprint compact.

### Use a React-rendered context menu

Rejected because a native Windows menu behaves more predictably outside the webview, remains compact, and better matches desktop conventions for hide, exit, settings, and layer actions.

## Consequences

- Rust must own window sizing, anchor preservation, monitor work-area clamping, and the native context menu through narrow commands.
- The React surface must model its explicit mode and coordinate click, drag, progress, learning, and placement transitions.
- Visual QA must cover all four modes at 100%, 125%, and 150% Windows scaling, including each screen edge and a negative-coordinate secondary monitor.
- Tests must verify that the idle hit region remains `232×258` logical pixels and that mode changes do not move the pet's foot-center except when work-area clamping is required.
- Existing FSRS, XP, persistence, language-pack, tray, and offline semantics are unchanged.
- The SVG pet can evolve visually without introducing a third-party character-license chain, but future external assets must be reviewed and recorded separately before use.

## Verification notes

- The 6px gesture threshold is enforced in the renderer; once exceeded, the renderer calls only the capability-scoped `core:window:allow-start-dragging` API and suppresses the click for that pointer sequence.
- A real Windows mouse-input smoke test moved the idle window from `(76,76)` to `(206,187)` and confirmed that the drag did not open the learning bubble. This is a regression constraint: do not replace the compact surface with a larger transparent hit area or enable click-through.
